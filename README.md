# 수소시설 인허가 AI 가이드

수소 사업자가 인허가를 물어보면, 국내외 법령에서 근거 조문을 찾아 답하는 챗봇입니다.

> 2026 WE-Meet 프로젝트 · 강원대학교 에너지신산업혁신융합대학사업단
> 기업 멘토: 한국가스안전공사 수소안전기술원

---

## 무엇을 하는가

```
질문  "수소충전소 안전거리 얼마야?"
  ↓
① 법령 32,217조각에서 관련 조문 검색      (내 컴퓨터, 무료, 0.1초)
  ↓
② 찾은 조문만 읽고 답변 작성              (제미나이 무료 API, 5~7초)
  ↓
답변  "제1종보호시설로부터 12m 이상 [고압가스 안전관리법 시행규칙 별표 8]"
     + 근거 조문 원문 + 이어질 질문 3개
```

핵심은 **AI가 법을 아는 게 아니라는 점**입니다. 매번 관련 조문을 찾아서 넣어주고,
AI는 그것만 읽고 정리합니다. 그래서 자료에 없으면 "없다"고 답합니다.

## 수록 자료

| 구분 | 수량 | 비고 |
|---|---:|---|
| 한국 법령 조문 | 4,098 | 법령 75종 (법률·시행령·시행규칙) |
| 한국 **별표** | 6,747조각 | 466종 — 안전거리·시설기준 등 실제 수치 |
| 별지 서식 | 491 | 이름·용도만 (원문은 링크로 안내) |
| 강원 액화수소 특구 | 5 | 공식 누리집 요약 (법령 아님을 본문에 명시) |
| 일본 법령 | 68 | 저탄소수소 공급·이용 촉진법 |
| **KGS Code(상세기준)** | 20,813조각 | 188종 — 별표가 넘긴 최종 기준 |
| **합계** | **32,217조각** | |

### 법 → 별표 → KGS Code

수치를 찾으려면 세 번 넘어가야 한다.

```
법 본문     "시설기준은 별표 8과 같다"          ← 수치 없음
별표 8      "상세기준은 KGS Code 에 따른다"      ← 여기도 없음
KGS FP216   "제1종보호시설 17m 이상"             ← 여기가 답
```

세 칸을 다 넣어야 답이 나온다. KGS Code 는 한국가스안전공사가 만드는 상세기준으로,
가스기술기준정보시스템(cyber.kgs.or.kr)에서 PDF 로 공개된다.

### 별표를 따로 넣은 이유

법령 본문은 "기준에 적합해야 한다(별표 8 관련)"에서 끝납니다.
**실무에 필요한 수치는 전부 별표(부속 표)에 있습니다.**

- 넣기 전 → "별표 8에 규정되어 있으나 내용은 제공된 자료에 없습니다"
- 넣은 후 → "산소 저장설비 1만 이하: 제1종보호시설 **12m**, 제2종 **8m**"

법마다 제공 방식이 달라 수집 경로도 둘로 나뉩니다.

| 법 | 별표 위치 | 처리 스크립트 |
|---|---|---|
| 고압가스법 · 수소법 · 도시가스법 | 본문 PDF 안에 포함 | `extract_annex.py` |
| 액화석유가스법 | 별표마다 개별 파일 | `fetch_annex_web.py` → `ingest_annex_pdfs.py` |
| 액법·산업융합촉진법·규제자유특구법 **시행령** | 별표마다 개별 파일 | `fetch_annex_by_lsiseq.py` → `ingest_extra_annexes.py` |

시행령·시행규칙 중 별표가 빠진 법령은 **없습니다**(54종 전부 수록).
「○○법」 본법에는 원래 별표가 거의 없고, 수치는 시행령·시행규칙에 있습니다.

## 구성 (폴더 안내)

처음 보는 사람은 **최상위 파일 + `data/`** 만 보면 됩니다. 나머지 폴더는 필요할 때만 엽니다.

```
├── app.py               서버 시작점 — python app.py
├── search.py            법령 검색 (뇌의 핵심)
├── rerank.py · facts.py · forms.py · distance.py · ollama_fallback.py
├── index.html           화면
├── warm_questions.txt   서버 뜰 때 미리 돌릴 질문
├── data/                로봇이 외운 법령 데이터 (jsonl·json)
├── pipeline/            법령 원문 수집·가공 — 데이터 다시 만들 때만
├── eval/                정확도 채점 — 정답셋·채점 기록·결과표
├── tools/               발표 준비·보고서 생성 도구
├── docs/                문서 — 진행 기록(PROGRESS.md), 해외 인허가 정리, 보고서
├── widget/              다른 홈페이지에 끼워 넣는 위젯
├── worker/              공개 주소 중계(Cloudflare Worker)
└── .githooks/           커밋 전 자동 검사
```

### 최상위 — 서버가 돌 때 쓰는 것

| 파일 | 역할 |
|---|---|
| `app.py` | 서버 — 검색 결과를 제미나이에 넘기고 답변을 흘려보냄 · 답변 캐시 · 공유 · 계산기 API |
| `search.py` | 법령 검색(BM25 + 뜻 벡터) · 조문↔별표 연결 · 시설유형 분류 · 기준일 · 개정 비교 |
| `rerank.py` | 재순위(크로스인코더) — 상위 후보를 질문과 함께 다시 읽어 줄 세움 (`BOT_RERANK=1`) |
| `distance.py` | 안전거리 계산기 — 별표·KGS 표에서 바로 찾음, `--check` 로 원문 대조 |
| `facts.py` | 확정 자료(수수료·서식·기간·안전거리) — 표 값을 근거 맨 앞에, `--check` 로 원문 대조 |
| `forms.py` | 별지 서식 파일 안내·내려받기 |
| `ollama_fallback.py` | 제미나이가 전부 막히면 로컬 LLM(Ollama)으로 답변 (`BOT_OLLAMA`) |
| `index.html` | 화면 — 대화 · 인용 링크 · 미확인 수치 밑줄 · 계산기 · 공유 |
| `.githooks/pre-commit` | 커밋 전 표 대조 + 검색 채점. 95% 미만이면 커밋 거부 |

### `eval/` — 정확도 채점

| 파일 | 역할 |
|---|---|
| `eval_run.py` | 정답셋 채점 · `--retrieval` 은 모델 없이 검색만 · 결과를 `eval_history/` 에 남김 |
| `eval_dashboard.py` | 채점 이력을 그림 한 장으로 → `정확도추이.html` |
| `eval_candidates.py` | 이용자 질문 기록에서 정답셋 후보 뽑기 |
| `eval_from_facts.py` | 확정 자료·안전거리 표에서 정답이 보증된 문항 자동 생성 → `eval_set_facts.json` |
| `eval_set_all.json` | 정답셋 112문항(20 + 50 + 후보 8 + 확정 자료 35) |
| `정확도측정*.md` | 채점 결과표 |

실행은 최상위에서: `python eval/eval_run.py eval_set_all.json --retrieval`

## 실행

### 가장 쉬운 방법 — 더블클릭

1. 이 저장소를 받아서 압축 풀기 (Code → Download ZIP)
2. **`start.bat`** 더블클릭 (맥은 `start.command`)
3. 검은 창이 알아서 진행합니다: 파이썬 확인 → 필요한 것 설치 → 구글 키 물어봄(한 번만) → 서버 켬 → 브라우저 자동 열림
4. 다음부터는 더블클릭하면 바로 열립니다. 검은 창을 닫으면 서버가 꺼집니다.

- 파이썬이 없으면 설치 페이지가 열립니다. 설치 화면 맨 아래 **"Add python.exe to PATH"** 에 꼭 체크하세요.
- 구글 키는 https://aistudio.google.com/apikey 에서 무료로 받습니다(클릭 두 번). 사람마다 따로 받으세요 — 하루 한도가 각자 생깁니다.
- 키 없이 Enter 만 쳐도 켜집니다. 법령 검색은 되고 답변 문장만 안 나옵니다.
- 처음 켤 때 1~2분 걸립니다(법령 32,217조각 색인). 두 번째부터는 10초.

### 명령어로 직접

```bash
pip install -r requirements.txt
echo "발급받은_키" > key.txt   # https://aistudio.google.com/apikey
python app.py                # http://localhost:8000
```

`key.txt`는 `.gitignore`에 있어 올라가지 않습니다. **키를 깃허브에 올리지 마세요** — 공개되면 몇 분 안에 남이 한도를 다 쓰고 구글이 키를 막습니다.

선택 옵션(환경변수):

| 변수 | 뜻 | 기본 |
|---|---|---|
| `BOT_RERANK=1` | 재순위 모델 켜기 (`pip install sentence-transformers`, 2.2GB). CPU 에서는 질문당 170초라 GPU 서버에서만 뜻이 있다(실측) | 끔 |
| `BOT_OLLAMA=http://127.0.0.1:11434` | 제미나이가 전부 막히면 넘어갈 로컬 LLM 주소 | 끔 |
| `BOT_OLLAMA_MODEL` | 그 모델 이름 | `exaone3.5:7.8b` |
| `BOT_PDF_DIR` | KGS Code PDF 폴더. 있으면 근거 카드에 "PDF n쪽" 버튼이 뜬다 (`pip install pymupdf`) | `~/Desktop/KGS_Code` |
| `BOT_CACHE_DAYS` | 답변 캐시 보관 기간 | 30 |

## 화면에서 할 수 있는 것

- **이어 묻기** — 앞 대화를 기억한다.
- **인용 클릭** — 답변 속 `[고압가스 안전관리법 제4조]`, `[KGS FP216 2.1.1.1]` 을 누르면 법령정보센터·KGS 원문으로 간다.
- **미확인 표기 밑줄** — 근거에서 못 찾은 수치·조문번호는 점선 밑줄. 누르면 근거로 내려간다.
- **체크리스트** — "뭐가 필요해?" 류 질문은 단계 · 해야 할 것 · 근거 · 제출 서식 · 관할 표로 답한다(설정에서 강제 가능).
- **기준일** — 설정에 날짜를 두면 그날 시행 중인 조문으로 답한다. "뭐가 바뀌어?" 는 개정 전후를 나란히 준다.
- **안전거리 계산기** — 용량을 넣으면 별표·KGS 표의 해당 칸을 그대로 보여준다. AI 를 거치지 않는다.
- **공유** — 대화를 저장해 `/s/아이디` 주소로 넘긴다. 받은 사람도 이어서 물을 수 있다.
- **지난 대화** — 이 브라우저에 최근 12개를 남긴다(서버로 안 보냄). 새로고침해도 다시 연다.
- **원문 패널** — 답변 속 근거 번호를 누르면 새 창 대신 옆에서 원문이 열린다. ↗ 는 원본 사이트.
- **되묻기** — 조건이 빠진 수치 질문("안전거리?")에는 답과 함께 조건을 고르는 단추를 준다.
- **👍👎** — 답변마다 평가. 👎 는 사유와 함께 `data/feedback.jsonl` 에 남고 정답셋 후보가 된다.
- **예열** — `BOT_WARM=1` 이면 `warm_questions.txt` 의 질문을 서버가 뜰 때 미리 돌려 캐시에 넣는다.

## 잘못된 답을 막는 장치

법령 챗봇은 틀린 숫자 하나가 치명적이라, 틀린 답을 "표시"하는 데서 끝내지 않고 "내보내지 않는" 쪽으로 겹겹이 막았습니다.

검색 단계
1. **갈래 보장** — 우산 개념(규제특례 = 실증특례·임시허가·신속확인)은 갈래마다 따로 찾아 1등을 반드시 넣는다. 조문이 부르는 다른 조문("제10조의3에 따른")도 딸려 온다.
2. **확정 자료** — 수수료·서식·특례 기간·회신 기간·안전거리·신고 수리 기간·안전관리자·벌칙·과태료·허가 종류·특정제조 대상·검사·정기검사·사용신고·수소용품·안전교육 19주제 55개 값을 `data/fact_tables.json` 에 두고 근거 맨 앞에 넣는다. `facts.py --check` 가 값마다 원문 인용을 대조한다(전부 일치).
3. **자료 없음 감지** — 검색 점수가 낮으면 비슷한 조문으로 대체하지 않고 "자료에 없다"고 밝힘

답변 단계
4. **근거 강제 + 문장마다 번호** — 제시된 조문 안에서만, 사실 문장마다 `[3]` 처럼 자료 번호를 달게 한다. 번호는 화면의 근거 카드와 같다.
5. **수치·조문·주체 대조 → 자기교정 → 삭제** — 답변의 수치·조문·서식번호·기관명(시장·군수·구청장, 한국가스안전공사, ○○부장관 등)을 근거와 대조한다. 하나라도 어긋나면 모델에게 고치게 하고, 그래도 남으면 그 문장(표는 그 행)을 지우고 "뺀 내용 n곳"으로 알린다.
6. **이중 검사** — 발표 모드(또는 `BOT_JUDGE=1`)에서는 답변과 **다른 계열** 모델(3.x가 답하면 2.5가 검수)이 문장마다 근거 유무를 채점해 불일치 문장을 회색 취소선으로 표시한다. 근거 번호가 없는 사실 문장은 점선으로 따로 표시한다.

운영 단계
7. **원문 병기** — 근거 조문 전문을 화면에 함께 표시, 인용은 원문 사이트로 연결
8. **캐시는 깨끗한 답만** — 경고·삭제·검수 불일치가 하나라도 있으면 저장하지 않는다
9. **발표 잠금** — `demo_prepare.py` 로 미리 돌려 사람이 승인한 답만 내보낸다(`BOT_DEMO_LOCK=1`)
10. **회귀 방지** — 커밋 전 훅이 표 값 대조와 검색 채점(112문항, 95% 미만이면 커밋 거부)을 돌린다. `git config core.hooksPath .githooks` 로 켠다.
11. **정답이 보증된 정답셋** — `eval_from_facts.py` 가 확정 자료·안전거리 표에서 문항 35개를 자동 생성한다. 정답이 원문 대조를 통과한 값이라 채점 기준 자체가 틀릴 일이 없다.

## 배포

오라클 클라우드 무료 서버(ARM 2코어)에 systemd 서비스로 올려 두었습니다.

```bash
sudo systemctl status hydrogen-bot     # 상태
sudo journalctl -u hydrogen-bot -f     # 로그
```

- 공개 주소: https://hydrogen-bot.tmdfoqhdl030.workers.dev (워커가 중계, 주소 고정)
- 접근 코드 없이 열려 있고, 대신 **한 사람당 시간당 30회**로 제한합니다(`BOT_RATE`).
- 서버에서는 API 키를 `~/hydrogen-bot/key.txt` 또는 `GEMINI_API_KEY` 환경변수로 읽습니다.
